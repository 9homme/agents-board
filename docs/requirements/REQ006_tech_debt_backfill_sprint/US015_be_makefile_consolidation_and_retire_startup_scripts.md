## Implementation notes
- **Process lifecycle (architecture D-013 Q3 — verbatim from `startup.sh`):**
  - `make dev-up`: launch `mcp-server`, `api-server`, `web` as backgrounded native processes (`&` shell syntax or `nohup` per the script convention). Capture each PID via `$!` into `.mcp.pid` / `.api.pid` / `.web.pid`. Redirect stdout+stderr to `mcp-server.log` / `api-server.log` / `web.log` at repo root.
  - Per-process status banner: `[dev-up] mcp-server started (pid 12345, log mcp-server.log)`.
  - Both `api-server` and `mcp-server` are invoked with `DATABASE_URL=$(DEV_PG_CONN)` set — NOT `DB_URL` (validates US010 alignment; architecture §3 US015 + AC scenario "DATABASE_URL is the only DB env var").
  - `make dev-down`: read each PID file, signal SIGTERM, wait a short grace, SIGKILL if still alive. Remove PID file once process is confirmed gone. Then a port-kill fallback against `:8080` (api), `:8081` (mcp), `:3000` (web). Idempotent on re-run (no PID files → exit 0).
- **Env-var defaults (architecture + US015 AC scenario "env-var defaults match `startup.sh`'s current behaviour"):**
  - `API_PORT ?= 8080`, `MCP_PORT ?= 8081`, web port `3000` (Next.js default), `FRONTEND_URL ?= http://localhost:3000`, `NEXT_PUBLIC_API_BASE_URL ?= http://localhost:$(API_PORT)`. All use `?=` so operators can override from the environment.
- **`PG_CONN := → ?=` flip** (absorbed from former US011 per D-014): Makefile line ~16. Re-locate the line by content match (`PG_CONN.*postgres://.*:15432`) if line numbering has drifted. The default URL is BYTE-IDENTICAL pre-flip vs post-flip — only the operator character changes.
- **`DEV_PG_CONN` default:** `postgres://agent_board:agent_board@localhost:5432/agent_board?sslmode=disable` (architecture §3 US015 + D-013 Q1 — native Postgres on `:5432`).
- **`dev-migrate` migrations source:** every file under `services/agent-board/migrations/*.up.sql` (the same set `e2e-seed` uses, applied in lexical order). The seed source is `tests/e2e/data/seeds/*.sql` (also lexical). Both target `$(DEV_PG_CONN)` via `psql`.
- **Preflight guards** (US015 AC scenario "fail gracefully when prerequisites are missing"):
  - `command -v psql >/dev/null 2>&1 || { echo "psql not in PATH — install postgres client and retry"; exit 1; }` style for `dev-migrate` / `dev-seed`.
  - Similar checks for `go` (used by `dev-up`) and `node` / `npm` (used by `web` startup).
  - "Best-effort guard" wording is fine (AC explicit) — the bar is "new dev does not hit a 500-line stack trace."
- **e2e-family byte-identical guarantee:** before committing, run `git diff Makefile | grep -E '^[-+]' | grep -E 'e2e-'` — the only allowed changes in this category are above-recipe variable additions (e.g. the new `DEV_PG_CONN`) and the `PG_CONN := → ?=` flip, both of which preserve resolved values.
